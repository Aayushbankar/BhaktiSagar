## 4. Defects

### QA-001 — Home, festival and date pages render no `<h1>` · **Medium → Fixed**

| | |
|---|---|
| **Type** | Accessibility / SEO |
| **Severity** | Medium |
| **Status** | **Fixed and verified** — `test.fail()` guard removed, test now passes |
| **Files** | `index.php` (renders `.page-h1`), `lib/seo.php` (`home_h1` / `festival_h1` / `date_h1` in all three languages), `assets/css/style.css` (`.page-h1`) |

**Original finding.** `index.php` declared an `<h1>` only for `.track-h1` and `.notfound-title`;
home, festival and date routes started their outline at `<h2>` (`.special-title`,
`#nowTitle`) — WCAG 1.3.1 / 2.4.6 gap and a missing primary on-page heading signal.

Measured `<h1>` count per route **after the fix**:

| Route | `<h1>` | `<h2>` | DOM nodes | Images |
|---|---:|---:|---:|---:|
| `/` (home, hi) | **1** | 2 | 733 | 37 |
| `/en` (home) | **1** | 2 | 733 | 37 |
| `/sa` (home) | **1** | 2 | 733 | 37 |
| `/festival/diwali-lakshmi-puja` | **1** | 2 | 871 | 46 |
| `/date/2026-11-15` | **1** | 2 | 687 | 34 |
| `/track/om-jai-jagdish-hare-lata` | 1 | 2 | 1316 | 73 |
| `/track/hanuman-chalisa` | 1 | 2 | 1246 | 73 |
| `/nope/xyz` (404) | 1 | 2 | 738 | 37 |

**Fix.** The first element of `.main-col` is now one server-rendered `<h1 class="page-h1">`
for `$route['ok'] && $route['kind'] !== 'track'`: home → `भक्ति सागर · श्लोक · भजन · आरती`
(`Bhakti Sagar · Shlokas · Bhajans · Aartis` in `en`), festival → the localised festival name
plus year (`app.js` uses the same `hi`/`name` fallback), date → `Panchang for {date}` /
`{date} का पंचांग`. Track and 404 pages keep their existing single `<h1>`, so no route can
render two.

**Verification.** `heading structure: exactly one <h1> per route` (10.9 s) passes on all 8
routes; the assertion is unchanged — it will fail again on regression. Full suite **82/82**.

### QA-002 — City note never renders on festival-free days · **Medium → Fixed**

| | |
|---|---|
| **Type** | Functional / UI |
| **Severity** | Medium |
| **Status** | **Fixed and verified** — both location tests pass |
| **Files** | `assets/js/app.js` (`renderPanchang()` festival block) |

**Original finding.** `renderPanchang()` wrote the festival chips and then `return`ed before
`renderPanchangNote()`, so on any day whose panchang carries **no festivals** the note
("पंचांग इस स्थान के सूर्योदय पर आधारित है – …") stayed `hidden` and empty. The first full run
after 2026-10-21 caught it: `city picker is populated…` and `switching to London…` failed on a
festival-free day while the same tests had passed on festival days.

**Fix.** The festival list is now built into a local variable and the row hidden *only* when
it is empty; `renderPanchangNote()` runs unconditionally whenever a panchang exists.

**Verification.** Both location tests pass standalone and in the full run; the earlier failures
were reproducible on demand (`--grep 50-location`), so a regression would fail loudly again.

## 6. Observations (no defect, worth knowing)

- **OBS-002 — third-party font dependency.** The only external request is `fonts.googleapis.com` (Mukta, Tiro Devanagari Hindi). First-party payload is just `style.css` + `app.js`. Self-hosting the fonts would remove an availability/privacy dependency and avoid the render-blocking third-party CSS. *Low.*
- **OBS-003 — lyrics coverage 49 %.** 30 of 59 tracks ship without lyrics. 12 pre-date this run: `shiva-tandava-stotram`, `shiv-amritwani`, `hanuman-chalisa`, `bajrang-baan`, `sankat-mochan-hanuman-ashtak`, `ganesh-amritwani`, `vishnu-amritwani`, `shanaishwara-shani-bhajan`, `durga-chalisa`, `shiv-stuti-ashutosh`, `ram-raksha-stotram`, `ekadashi-special-bhajans`. The other **18 are the tracks added by the catalogue expansion** and are new lyrics work. All 30 correctly render the empty state (no toolbar, no stanza badge); `ekadashi-special-bhajans` is a *collection*, not a text — expected to stay empty. *Accepted — 18 new lyrics pending.*
- **OBS-004 — 24 unverified lyric stanzas.** `data/lyrics.php` carries 24 `// CHECK:` markers (lines 90–251) for text recalled from memory. Proofread with `grep -n "CHECK" data/lyrics.php`. *Open, content task.*
- **OBS-005 — playback is the costliest area.** Player suite = 44.6 s of a 229.9 s run; `auto-advance` alone 9.9 s. Stable (0 flakes across this run), but it is where a future flake would appear first.
- **OBS-006 — home DOM grew with the catalogue and the darshan section.** 554 → 627–733 nodes and 24 → 31–37 images on `/` (expanded default-slot grid, `.page-h1`, plus 6 lazy darshan thumbnails; the exact figure varies with the current time slot's grid). Still far inside the 6000-node budget, and long tasks remain 0. *Watch if the catalogue doubles again.*
- **OBS-007 — one pre-existing video had silently gone embed-blocked.** The full playback sweep (`tools/verify-player.mjs --file tools/ids-all.txt`) scored **58/59**: `hanuman-chalisa` (`F2sK70nF3OY`) returned YouTube error `150`. It was swapped for `AETFvQonfV8` (same T-Series / Hariharan–Gulshan Kumar recording, subtitled) and the sweep re-run → **59/59 playable**. Root cause of the first sweep's alarming result: YouTube honours *domain-restricted* embedding, so the harness must load from the app's own origin — `.htaccess` now allows exactly `tools/player-check.html` and nothing else under `tools/`. *Closed.*
- **OBS-008 — 6 of the 12 Jyotirlingas have no live stream yet.** Srisailam/Mallikarjuna, Parli Vaijnath, Bhimashankar, Rameshwaram, Grishneshwar and Nageshwar were searched on 2026-10-21 (including YouTube's live-only filter) and returned no temple darshan stream; Trimbakeshwar was sourced and added on 2026-10-22 (`EMMWSBPvbrE`), taking the live count to **6/12**. They ship as `youtube_id: null` and are hidden by `renderJyo()`; add `youtube_id` + `channel` + `verified_on` to `data/jyotirlingas.php` when one appears — no seeding, no code change. Live streams also *expire*, so re-check with `node tools/live-check.mjs <ids>` before trusting an id. *Open — sourcing task.*
